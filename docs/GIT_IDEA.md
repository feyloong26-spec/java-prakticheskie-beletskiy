# Git и IntelliJ IDEA

Белецкий А.Ю., УИБО-03-24. Отдельный проект практических работ по Java.

## Требование методички

В «ПР1 часть 1.pdf», на последней странице (номер в документе 14), пункт 2 требует создать собственный Git-репозиторий. Пункт 8 требует загрузить результаты через IDE и продемонстрировать преподавателю.

## Размещение через IDE

1. Откройте эту папку проекта в IntelliJ IDEA и импортируйте `pom.xml`.
2. Если папка ещё не содержит Git, выберите **VCS → Create Git Repository**, указав именно корень этого Java-проекта.
3. Для нового репозитория используйте **Git → GitHub → Share Project on GitHub**: имя `java-prakticheskie-beletskiy`, публичный доступ. Если репозиторий уже создан, добавьте его точный HTTPS-адрес через **Git → Manage Remotes** вместо повторного создания.
4. Проверьте адрес `origin`: он должен указывать на отдельный репозиторий практических работ. Не выбирайте `f1-fun-app` и не открывайте проект FanPick.
5. В **Commit** включите `src`, `.run`, `docs`, `pom.xml`, `README.md`, `.gitignore`; выполните commit, затем **Git → Push**.
6. На GitHub проверьте наличие файлов, отметку **Public** и последний commit. Откройте ссылку без входа в аккаунт, чтобы подтвердить публичный доступ.

## Демонстрация преподавателю

Откройте README на GitHub, перейдите по номеру нужного задания к его `Main.java`, затем в IntelliJ IDEA выберите соответствующий запуск, покажите исходный код и результат. UML-диаграммы доступны по ссылкам в README. Для подтверждения пункта 8 покажите окно Push/историю Git в IDE после фактической загрузки через IDE.

Не утверждайте, что загрузка выполнена через IDE, если она сделана другим способом. Наличие архива или локального проекта не подтверждает публикацию.
